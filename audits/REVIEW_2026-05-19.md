## Overall verdict

The contract is **clean, defensive and architecturally sound**. The atomic fan-out + self-pay short-circuit + failover-to-root logic is correctly implemented and conservation holds (I11).

The main objection to "ready for testnet" is the **absence of tests** — `BtcbotRouter.t.sol` is explicitly a skeleton covering constructor + setters only. No swap, fan-out, failover, reentrancy or pause tests. This alone blocks §9 sign-off.

Beyond that: **2 HIGH**, **5 MEDIUM**, **6 LOW**, and **3 spec↔code drifts** to reconcile.

---

## HIGH — fix before testnet

### H1. Ambiguous semantics of `minUsdtOut`

The argument is passed to Pancake as the swap floor **and** used in the user-net check (`usdtOut < minUsdtOut + totalCommission`). Both usages are semantically inconsistent and the trader has to guess which one applies.

For the contract to behave the way the spec invariant I1 states (*"userReceived ≥ minUsdtOut"*), the trader must pass `minUsdtOut = userMinNet + totalCommission`. That's an implicit contract that will produce a silent misuse one day.

Proposed fix: rename to `minUserReceived`, move the `totalCommission` sum before the swap, compute `pancakeMinOut = minUserReceived + totalCommission` internally, pass that to Pancake. Defense-in-depth check `usdtOut >= pancakeMinOut` post-swap. See `H1_patch.md`.

### H2. Missing test coverage

The `test/BtcbotRouter.t.sol` skeleton covers constructor + setters only. The spec §5.1 test plan lists ~20 critical cases that are **all missing**:

- `test_swapAndDistribute_happyPath` — missing
- `test_swapAndDistribute_conservation` — missing
- `test_swapAndDistribute_failoverToRoot_*` (revert + returns-false + allTiersFail) — missing
- `test_swapAndDistribute_selfPay*` — missing
- `test_swapAndDistribute_reentrancy` — missing
- `test_swapAndDistribute_atomicityOnSwapFailure` — missing
- `test_swapAndDistribute_revertsOnSlippage` / `_revertsOnCommissionAboveCap` / `_revertsWhenPaused` — missing
- fork tests — missing

Mocks (`MockERC20`, `MockPancakeRouter`, `MockPermit2`) don't exist either. They are provided in `test/mocks/` alongside this review.

## MEDIUM — fix before mainnet

### M1. No two-step ownership transfer

`transferOwnership(newOwner)` is single-step. If a wrong address is passed, the contract is permanently bricked (no more `setPaused`, `setTrader`, `rescueToken`, or further `transferOwnership`). For a contract with an emergency kill-switch, this is a potential catastrophe.

Fix: adopt OZ `Ownable2Step` pattern (introduce `pendingOwner` + `acceptOwnership`).

### M2. Permit token check uses `require` string instead of custom error

```solidity
require(permit.permitted.token == BTCB, "permit token != BTCB");  // line 200
require(permit.permitted.token == USDT, "permit token != USDT");  // line 296
```

Inconsistent with the rest of the contract (custom errors). Add `error WrongPermitToken();` and use it.

### M3. `abi.decode(ret, (bool))` can revert on unexpected return-data length

```solidity
bool ok = success && (ret.length == 0 || abi.decode(ret, (bool)));
```

If the token returns 64 bytes instead of 32, `abi.decode` reverts in *this* function — killing the whole swap instead of falling over to root. In practice USDT BSC is standard, but the defense-in-depth pattern is:

```solidity
bool ok = success && (
    ret.length == 0 ||
    (ret.length == 32 && abi.decode(ret, (bool)))
);
```

### M4. `amounts[1]` is brittle for multi-hop swaps

```solidity
uint256 usdtOut = amounts[1];   // line 224
btcbOut = amounts[1];           // line 314
```

If anyone adds a hop in `path`, `amounts[1]` becomes the intermediate token, not the final output. Use `amounts[amounts.length - 1]`.

### M5. Cap check ordering

```solidity
if (totalCommission * BPS_DENOMINATOR > usdtOut * MAX_COMMISSION_BPS) revert CommissionTooHigh();  // line 234
if (usdtOut < minUsdtOut + totalCommission) revert InsufficientOutput();  // line 237
```

Functionally OK, but on a trade where totalCommission > usdtOut, the cap check fires first and masks the real problem ("usdtOut too low to cover commission"). Swap order for clearer error messages. Very minor.

## LOW — consider

### L1. Self-pay: deduct-then-undeduct readability

```solidity
userReceived -= part;          // line 247, applied to ALL tiers
// ...
if (recipient == user) {
    userReceived += part;       // line 255, cancels for self-pay
    emit TierSelfPaySkipped(...);
    continue;
}
```

Correct but reads strangely. Cleaner:

```solidity
if (recipient == user) {
    emit TierSelfPaySkipped(user, tierLabel, part);
    continue;                   // userReceived unchanged
}
userReceived -= part;           // only deduct when actually paying
```

### L2. `unchecked { ++i }` in fan-out loop

Micro gas-save (~500 gas total at N=6). Apply when the loop is touched anyway.

### L3. No guard for `recipients[i] == address(0)` with `parts[i] > 0`

The transfer to `0x0` will revert (most ERC20s reject), so the failover routes to root. Functionally OK but noisy. Explicit guard would be cleaner.

### L4. Pragma not pinned

`^0.8.24` allows 0.8.24+ minor upgrades. For audit reproducibility, pin to exactly `0.8.24` and lock in `foundry.toml`.

### L5. `MAX_COMMISSION_BPS` is `constant`

To change the cap, redeploy + re-permit all users. Documented in spec §7 #5 as intentional. OK for V1 with 30% target + 5pp margin, but flag for revisit.

### L6. `Rescued` event has no `from` field

The `onlyOwner` modifier makes the caller implicit, but for off-chain indexers an `indexed initiator` field would make BscScan filtering cleaner.

## Spec ↔ code drift

### D1. `event Paused` (spec) vs `event PausedSet` (code)

Pick one. Code currently emits `PausedSet`; spec §3.2 declares `Paused`. Align.

### D2. `TierFailoverToRoot` drops `bytes reason`

Spec §3.2:
```solidity
event TierFailoverToRoot(..., uint256 amount, bytes reason);
```
Code:
```solidity
event TierFailoverToRoot(..., uint256 amount);
```

The `bytes ret` from the failing call is captured but never emitted. Debug info lost — useful to know whether the failure was a revert, returns-false, or blacklist. Either add `ret` to the event, or remove from spec.

### D3. `InvalidRecipientArray` / `InvalidPartsArray` errors unused

Spec §3.3 declares them. Code doesn't. They're effectively unreachable because the function signature `address[N_TIERS] calldata` enforces length at the ABI level. Either remove from spec or add explicit defensive checks.
